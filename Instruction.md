# **Инструкции и контекст разработки ИИ-системы для КЦ**

Этот документ предназначен для ИИ-агента в Cursor. Он описывает архитектуру, стек и ключевые требования для разработки прототипа голосового ИИ-агента и системы суфлирования.

## **1. Описание проекта**

Создание комплексной системы для автоматизации контакт-центра. Система включает входящую линию с голосовым ботом (Voice Bot), систему реального времени для подсказок операторам (Agent Assist/Суфлер) и аналитический модуль.

## **2. Технологический стек (Прототип)**

- **Backend:** Python 3.11+, FastAPI (полная асинхронность).
- **Frontend (Admin/Playground):** Next.js, Tailwind CSS, shadcn/ui.
- **Базы данных:** Qdrant (векторная БД для RAG), PostgreSQL (метаданные и настройки).
- **Интеграции (API):**
- **STT (ASR):** Deepgram (через WebSockets для потоковой передачи).
- **LLM:** OpenAI (gpt-4o-mini для скорости).
- **TTS:** ElevenLabs (с поддержкой стриминга).
- **Инфраструктура:** Docker, Docker Compose.

## **3. Ключевые архитектурные компоненты**


| Компонент         | Функция                                   | Технические особенности                                                                                            |
| ----------------- | ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| **Voice Engine**  | Обработка аудиопотока в реальном времени. | Использование WebSockets для минимизации задержек. Пайплайн: Audio -> STT -> LLM -> TTS -> Audio.                  |
| **RAG Module**    | Поиск ответов по базе знаний.             | Семантический поиск в Qdrant. Запрет на генерацию ответов вне контекста базы знаний.                               |
| **Orchestrator**  | Управление логикой диалога.               | Маршрутизация (intent detection). Отделение консультационных тем от операционных (требующих перевода на человека). |
| **Control Plane** | Админ-панель.                             | Управление промптами, голосами, загрузка документов в базу знаний, плейграунд для тестов.                          |


## **4. Жесткие требования и метрики (из ФТ)**

- **Задержка (Latency):** Общее время ответа бота не должно превышать 1.5 секунды.
- **Точность (Intent Accuracy):** Определение тематики обращения — не ниже 80%.
- **Локализация:** Поддержка русского и узбекского языков (включая региональные диалекты).
- **Безопасность:** В финальной версии данные не должны покидать контур компании (учитывать при проектировании интерфейсов для будущей замены API на локальные модели).
- **Интеграции:** Будущая совместимость с Webitel и CRM Creatio.

## **6. Рекомендации по написанию кода**

1. **Async First:** Весь код бэкенда должен быть асинхронным. Избегать блокирующих вызовов в основном потоке обработки звука.
2. **Error Handling:** Реализовать устойчивость к разрывам WebSocket-соединений.
3. **Logging:** Логировать каждый этап обработки (STT latency, LLM latency, TTS latency) для мониторинга 1.5-секундного лимита.
4. **Modularity:** Использовать паттерн "Стратегия" для сервисов STT/TTS/LLM, чтобы была возможность мгновенного переключения провайдеров.
